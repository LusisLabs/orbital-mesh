01 / Principles

Designed for repeated operation.

Use the same restraint expected from a production console. Decoration should never compete with state, risk, evidence, or authority.

Dense, not crowded

Panels should carry enough operational detail for scanning. Space is used to separate decisions, not to create a marketing layout.

Semantic by default

Green, amber, and red are reserved for state. Proof cyan is reserved for hashes, roots, signed packets, and exported evidence.

No implied autonomy

Copy and visuals must reinforce gates, allowlists, scoped actuators, and human steering before production mutation.

04 / Logo

Bounded mesh, central policy gate.

The mark is useful when it stays quiet. It should identify the product, not behave like an animated status indicator.

Use

  • Use `logo.svg` unchanged for docs, decks, and repo identity.
  • Minimum size: 24px UI, 48px docs and decks.
  • Use on dark neutral surfaces first.
  • Keep clearspace equal to half the mark width.

Do not

  • Do not animate the mark in production surfaces.
  • Do not use semantic state colors as decoration.
  • Do not place the mark inside oversized badges.
  • Do not use it as a progress spinner.

06 / Language

Precise claims only.

Public language should sound like a control plane with proof, not a general AI automation pitch.

Use

  • Policy-guided operator control plane.
  • Bounded remediation for private infrastructure.
  • Operator-steerable runs with evaluation gates.
  • Audit-ready run evidence and Merkle-backed event history.
  • CROPS: Cloud, Reliability, Ops, Platform, and Security.

Avoid

  • Self-healing infrastructure.
  • Autonomous production AI.
  • AI-powered as a generic value claim.
  • Best, first, or safest without measured proof.
  • Protocol language where no protocol contract is being described.
