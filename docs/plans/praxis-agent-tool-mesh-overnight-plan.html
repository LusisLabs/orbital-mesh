Praxis Agent-Tool Mesh Overnight Build Plan

Build Praxis as a Mesh-governed MCP connector factory. Praxis generates candidate tool servers and workflow contracts. Akto supplies API security evidence. ACP supplies the supervised agent session surface. Mesh remains the authority for certification, policy, approvals, audit, deployment posture, and revocation.

Product posture Governed agent-tool mesh
Overnight target Contracted vertical slice
Hard boundary Mesh owns authority
Validation pnpm gates, no tail

Target Architecture

Praxis expands the mesh. It does not replace Mesh.
Input
API specs and SOPs OpenAPI, Postman, HAR, traffic exports, source-derived endpoint lists, process documents.
Generate
Praxis contract builder Extracts tool candidates, workflow hints, auth needs, schemas, mutation classes, and evidence gaps.
Scan
Akto evidence lane Imports API inventory, sensitive data findings, DAST results, auth risks, and CI scan status.
Certify
Mesh connector gate Maps security and ownership evidence into scopes: denied, read-only, approval-required, staging, pilot.
Supervise
ACP operator session Human reviews tool proposals, permission requests, generated diffs, and deployment posture.
Expose
MCP server runtime Agents call only certified MCP tools. Mesh records events, audit, revocation, and outcomes.
Authority

Mesh decides

Policy, certification, approvals, run events, proof continuity, readiness, and bounded actuation remain Mesh-owned.

Generation

Praxis proposes

Generated servers are candidates until contracts, security evidence, and connector certification admit them.

Security

Akto informs

Akto findings are evidence. Critical or unresolved findings block certification; they do not become policy by themselves.

P0 scope lock Praxis generates candidate MCP contracts and tool-server manifests. Akto supplies advisory security evidence. ACP supplies supervised operator-session artifacts. MCP exposes only what Mesh certification admits. Mesh owns connector policy, certification, approval, audit, bounded execution, proof continuity, readiness posture, and revocation. Managed hosting, marketplace distribution, live DAST triggers, and pilot runtime authority stay out of the overnight MVP until the proof packet path exists.

One fixture source bundle produces a normalized, cited source packet with explicit unknowns and evidence gaps. pnpm run lint:fast; source-ingest unit tests.

Candidate MCP tools are generated but not certified. Mutating tools default to denied or approval-required until certification. Golden fixture tests; pnpm run test:focused once wired into focused suite.
P4 praxis.akto-security-evidence.v1 Akto lane Add optional Akto result importer first. Later add trigger support for CLI/CI scans. Normalize inventory, findings, severities, affected endpoints, and scan status. Akto evidence can block or downgrade generated MCP tools. Missing Akto is degraded-safe and visible in readiness. Fixture import tests; no live DAST by default; pnpm run lint:fast.
P5 mesh.connector-certification.praxis.v1 Certification bridge Map generated tool contracts plus Akto evidence into connector-certification.registry.json compatible certification packets and readiness blockers. Read-only tools can reach staging-ready when evidence passes. Mutating tools require approval, ownership, policy, and security clearance. pnpm run verify:contracts; integration tests for readiness downgrade and blocker rendering.
P6 praxis.acp-session.v1 ACP supervised agent Expose a Praxis proposal agent through ACP. Permission prompts map to Mesh approval records; ACP cannot grant runtime authority. Session artifact records prompt, source packet, proposed tools, permission decisions, and generated contract refs. Adapter tests with fake ACP client; pnpm run test:focused after inclusion.
P7 meshapp.praxis-operator-ui.v1 Operator UI Add a Praxis panel to show uploaded sources, generated tools, Akto findings, certification state, approval posture, and MCP endpoint readiness. Operator can inspect why a tool is denied, read-only, approval-required, or staged. No invisible authority upgrades. pnpm --dir meshapp/frontend run lint; targeted UI tests.
P8 praxis.e2e-proof-packet.v1 Vertical proof Seed a sample API plus SOP, generate candidate MCP tools, import Akto fixture evidence, certify read-only tool, deny unsafe mutation, expose dry-run MCP endpoint. One exported proof packet binds source -> generated contract -> security evidence -> certification -> MCP readiness -> operator decision. pnpm run verify:full; run export verifier once added.
P9 praxis.security-readiness.v1 Security hardening Extend threat model, data classification, procurement/security package, credential rotation proof, and docs for Praxis/Akto/ACP/MCP boundaries. Security docs distinguish repository evidence from target-environment proof. Active DAST requires explicit test-safe target. Add verify:security only if backed by real scripts; keep pnpm run lint as heavy gate.
P10 praxis.pilot-runtime.v1 Pilot runtime Deploy generated MCP server in a bounded runtime, add revocation path, credential boundary checks, audit sink refs, and rollback/deactivate controls. One pilot-like environment proves generated MCP tool use under Mesh approval and revocation with no raw secret leakage. Production-like proof packet, Postgres state, connector certification drill, and pnpm run lint.
Pn praxis.expansion-roadmap.v1 Backlog Marketplace templates, tenant isolation, private-cloud deployment, continuous Akto scanning, source-code API extraction, generated workflow simulation, pricing and packaging. Each expansion item has proof requirements before marketing or production-readiness claims. Separate milestone gates. Do not fold backlog into overnight MVP.

Overnight Execution Order

Measure twice, cut once. Contract first, runtime after.
First six hours
00:00-00:45P0 scope lock. Write state slices, non-goals, artifact names, and acceptance tests before touching runtime.
00:45-02:15P1 schema-only contracts and contract tests. No UI, no adapters, no generated server code until schemas pass.
02:15-04:00P2 source-ingest fixture path for OpenAPI, SOP Markdown, and redacted traffic reference.
04:00-06:00P3 deterministic MCP contract generator. Start with manifest output, not managed deployment.
Second six hours
06:00-07:30P4 Akto evidence importer using fixture outputs. No live active scanning by default.
07:30-09:00P5 certification bridge and readiness blockers for generated connectors.
09:00-10:30P6/P7 minimal ACP session artifact and Meshapp panel for review state.
10:30-12:00P8 proof packet and focused validation. Stop on evidence truth, not cosmetic greenwashing.
Detached run rule For an actual overnight build run, use a named tmux session and a durable run directory under .mesh-runtime-state/praxis-overnight/<stamp>/ with manifest.json, report.md, and lane logs. Do not use tail. Poll manifests and final report files.

Validation Gates

Current root scripts use pnpm. Keep pnpm run lint as the heavy root gate.
Fast preflight pnpm run lint:fast for contracts plus focused Python compile checks.
Contract truth pnpm run verify:contracts before generated UI types or runtime claims.
Focused behavior pnpm run test:focused after adding source ingest, generation, certification, or session behavior.
Frontend surfaces pnpm --dir meshapp/frontend run lint and pnpm --dir web run lint when generated contracts or UI change.
Full gate pnpm run verify:full before calling the vertical slice complete.
Heavy gate pnpm run lint remains the root hard gate; do not replace it with narrow checks.

Hard Risks

These are blockers, not polish items.
Authority creep

Generated tools bypass Mesh

Block by default. Generated MCP servers are candidates until connector certification admits exact scopes. ACP permission requests become Mesh operator decisions, not direct runtime grants.

Security scan harm

Active DAST against unsafe targets

Start with Akto result import and fixtures. Live scans require explicit test-safe target, rate limits, target ownership, and operator approval.

Secret leakage

Specs and traffic carry credentials

Persist refs, hashes, redacted summaries, and credential environment variable names. Never commit API keys, bearer tokens, cookies, kubeconfigs, or customer traffic.

False certainty

SOPs become executable truth

SOPs are context and policy evidence. They can suggest workflows, approvals, and owners. They cannot certify behavior without API tests and Mesh policy gates.

Overnight sprawl

Too many surfaces change at once

Ship schema, source fixture, generator, Akto import, certification bridge, and proof packet first. Managed hosting and marketplace wait for Pn.

Dirty tree collision

Unrelated changes get mixed in

Start and finish with status. Do not stage unrelated files. If a touched file has user edits, inspect and preserve them.
